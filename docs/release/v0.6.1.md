# net-io v0.6.1 - Patch

**A security fix for PROXY with TLS on the reactor, and the two requests serve-net needs from 0.6.** No API change; every 0.6.0 program builds unchanged.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies.

## Security

**Upgrade if you run sessions on the reactor behind PROXY with TLS.** Bytes that arrived with the PROXY header reached the session as if they had been decrypted once the handshake finished: bytes put in front of the real ClientHello were read as the TLS peer's. They now go to the TLS engine, which refuses them. A ClientHello in the header's segment no longer stalls the handshake. Affects 0.5.0 and 0.6.0; the blocking pool was not affected.

A session that wrote more than one output buffer per flush (a large reply, a stream, a WebSocket echo) spent the shared buffer budget within seconds: its spare buffers were never reused. Other connections then stalled waiting for buffers, and the session itself spun its worker. Any client asking for a large reply could cause it, on both drivers. Outputs now reuse their buffers, and a connection whose push the budget refuses with nothing queued is closed with `Limit(BufferBudget)` instead of spinning.

A session that survived a read timeout while part of a message waited in its buffer could make a reactor worker panic and drop every connection on it. Fixed.

## Fixed

- A `Completer::post` reaches a connection that waits for input, not only a parked one, on both drivers: a WebSocket can be written to from another thread.
- A survived idle timeout (a trim from a timer) gives the connection's idle buffers back while its next receive is out: about 1.8 KB per idle connection, not 4.9 KB.
- `Server::shutdown` with an injected clock no longer waits for ever on a lingering connection.
- No connection is admitted after the door closed in the middle of an accept batch, and a drain answers a request that already arrived before it closes the connection.
