# net-io v0.7.0 - Hardening

**Attacked, fuzzed, and soaked.** v0.7.0 goes through the whole crate again, and every defect of medium severity or above that turned up is fixed, each with a test that failed first. It adds an attack test for every threat in `docs/SECURITY.md`, stateful fuzz targets that run every night, and a 24-hour soak with normal and hostile peers. It also covers the transport needs a database brings: bulk files that cannot starve small requests, receiving into a file, and a client that survives its server.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies; the few OS calls `std` does not expose go through the crate's own small, tested FFI layer.

## What's in 0.7.0

- **A client that survives its server.** `Backoff` (100 ms doubling to 30 s, each delay drawn from the upper half of its step) and `TcpConnection::connect_retry` reconnect through a restart or a failover, resolving the name again on each attempt. A reset during connect (a server refusing at its cap) and a host out of local ports are retried too, since both pass by themselves. `probe` tells an idle pooled connection that is still open from one whose peer closed, without consuming anything. `drain` closes from the client side without a reset.
- **Bulk transfer that gives way.** The reactor sends at most 256 KiB of file between two looks at the OS. A small request beside a 4 GiB stream to a fast reader now sees a p99 of 213 to 216 us, against 258 to 305 us before.
- **Receiving into a file.** `TcpConnection::recv_file` writes what arrives into a file at an offset, by `splice` on Linux, under the usual read deadlines and minimum rate.
- **Fuzzing that keeps going.** Stateful targets for the timing wheel, the minimum-rate counter, and the UDP guard, each checked against a model, join the parser targets. Every target runs 30 s on each push and 10 minutes every night, with the corpus kept.
- **The soak.** `tests/soak.rs` runs normal clients, a reconnecting client pool, big writers, slowloris peers, slow readers, idle hoarders, floods at the cap, and kills against one server. It samples memory, descriptors or handles, and open connections. It ran 24 hours on Linux and on Windows and 5.5 hours on macOS: 18 billion exchanges and 113,000 kills on Linux and Windows together, with no stuck exchange and memory that levels off at its high-water mark.
- **Who connected, under mutual TLS.** `TlsInfo::peer_spki_sha256` carries the SHA-256 of the verified client certificate's public key, set by the TLS engine, so a session can map a peer to a principal. The hash stays the same when a certificate is reissued with the same key.
- **`descriptor_limit()`** is public, so a server can put its own soft cap under the one net-io picks.

## Security

**Upgrade if you run TLS, PROXY, or untrusted UDP peers.** The fixes here that also affect 0.6.0 users were released in 0.6.1. The ones that change behaviour a configuration may rely on are only here:

- A TLS gate denial is an encrypted record, sent once; it was written in the clear between records.
- A panic in a TLS engine or an event sink no longer costs a worker its connections: both run behind panic boundaries, and each worker has a last one that accounts for whatever a panic left.
- A released buffer is wiped over everything it held since its last wipe, not only its current length, so a consumed request or decrypted plaintext cannot reach the next owner.
- A listener's own `max_connections` can no longer lift the server's cap; it is refused at build (use `max_per_listener`).
- Windows: a pipe listener cannot join a pipe another user created under its name, and clients can check who serves a pipe. Hand-off refuses a socket the process already owns and makes received sockets non-inheritable. Binding an AF_UNIX path no longer deletes a reparse point that is not a socket file.
- Unix: a cut `SCM_RIGHTS` message closes every descriptor it carried.
- UDP: verification is per address and port and expires (60 s by default), in its own bounded table, so a verified IP is no longer an unlimited reflection target on every port.
- The public `Driver` holds each registered socket until it is deregistered, so a dropped socket's number cannot be reused by a connection that then receives another connection's bytes.

## Changed

- `Driver::register` takes a `SharedSocket`; `BorrowedSocket` is no longer public.
- Timeouts over a year and `max_connections` over 2^20 are refused at build.
- UDP protocols call `mark_verified` on each proof, since verification now expires.
- A sub-second `Linger::Timeout` rounds up to one second on every OS.

## Known gaps

The register in `dev/ROADMAP.md` lists what is accepted for now, each with its reason and the version that closes it. The soak on macOS runs 5.5 hours, the most GitHub's hosted runners allow, not 24. On macOS a client whose receive buffer is full can miss the reset of a connection the server killed, and waits until its own read timeout: a few times an hour in the soak, never on Linux or Windows. The cause is macOS's reset rate limit: with `net.inet.tcp.rst_rlc_enable=0` the soak lost none (D-193). Two `Server`s sharing one listening socket in one process on Windows are not yet shown to work. The 1.2x speed gate is re-run on a dedicated machine before 1.0.
