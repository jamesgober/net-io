# net-io v0.7.3 - Patch

**A fix to `close_door`.** No API change: every 0.7 program builds unchanged. 0.8.1 has the same fix.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies.

## Fixed

- **`close_door` and an accept under way.** `close_door` set a flag and woke the accept threads, so an accept that had already passed its door check could still admit one more connection after `close_door` returned. It now waits for any admission in progress to finish: when it returns, no connection is admitted until the next `open_door`. The connection whose accept had begun is served, not reset, so a hand-off restart does not drop a client whose connect already completed. Called from a gate's `admit` on the thread of an admission, `close_door` closes the door without waiting.
- Cost: one extra atomic load when each admission ends, and `close_door` now takes as long as the longest admission in progress, which is bounded by the gate's `admit`.

## Who should upgrade

Everyone on 0.7 who closes the door and then counts, hands off, or stops on what was admitted: `cargo update -p net-io`. 0.8.1 has the same fix.

## What's next

`0.8` is the current line, and 0.8.1 has this fix too. Moving to it brings flush-then-close, a drain hook, and workers kept for a listener.
