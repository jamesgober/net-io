# net-io v0.7.2 - Patch

**A security release.** This release fixes two critical and three high defects in 0.7.1. No API change: every 0.7 program builds unchanged. 0.6.3 carries the same fixes for the 0.6 line. Upgrade, especially if you use Windows named pipes or listener hand-off, TLS on the reactor, or Unix sockets in a shared directory.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies.

## Security

- **Windows, reactor, named pipes (critical).** When the gate denied a write on a named-pipe connection, the denial's write reported to the worker's completion port, and the worker took it for one of its own operations: the process could crash or its memory be corrupted. Pipe IO outside the driver no longer reports to the port, and the port now ignores any completion it did not start.
- **Windows listener hand-off (critical).** A forged hand-off message could make the receiving process take over one of its own sockets (giving it two owners), or close it. The receiver now refuses any socket that is not a fresh duplicate and leaves it as it was, and the sender must run as the same user and have started before the pipe connected, also when the receiver is the side that dialed.
- **Reactor with TLS (high).** A TLS connection took 128 KiB of the shared buffer budget at accept, before the client sent anything, and held it until its handshake deadline; enough silent connections stalled every other connection, and the budget did not come back afterwards. TLS buffers are now taken when the first bytes arrive, unfinished handshakes hold at most a quarter of the budget, and a worker gives back buffers it no longer needs, across size classes.
- **Unix sockets (high).** Binding in a directory other users can write to set the mode and owner by path, which a symbolic or hard link put in place could point at another file. The mode and owner are now set relative to the open directory, or inside a private directory when others can change entries; a directory every user can write to without the sticky bit is refused with `ConfigReason::InsecureDirectory`.
- **Windows named pipes (high).** Windows rewrites `/` and `..` in a pipe path, so a pipe name could open a file or a network path. Names with `\` or `/`, the names `.` and `..`, and names over 247 characters are refused. A name with `/` used to mean a nested pipe name; use another character.

## Added

- `ConfigReason::InsecureDirectory`, `PoolStats::freed`.

## Who should upgrade

Everyone on 0.7: `cargo update -p net-io`. Programs on 0.6 get the same fixes in 0.6.3. Older versions with these defects are yanked once both patches are out.

## What's next

`0.8.0`: integration with real consumers (bouncer-io's flush-then-close, serve-net's drain hook and dedicated workers, tls-net's handshake work) and the remaining lower-severity fixes.
