# net-io v0.6.3 - Patch

**A security release for the 0.6 line.** An independent review of 0.7.1 found two critical and three high defects that 0.6.2 has as well; this release fixes all five, as 0.7.2 does for the 0.7 line. No API change: every 0.6 program builds unchanged.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies.

## Security

- **Windows, reactor, named pipes (critical).** When the gate denied a write on a named-pipe connection, the denial's write reported to the worker's completion port, and the worker took it for one of its own operations: the process could crash or its memory be corrupted. Pipe IO outside the driver no longer reports to the port, and the port ignores any completion it did not start.
- **Windows listener hand-off (critical).** A forged hand-off message could make the receiving process take over one of its own sockets, or close it. The receiver now refuses any socket that is not a fresh duplicate and leaves it as it was, received sockets are no longer inheritable, and the sender must run as the same user and have started before the pipe connected.
- **Reactor with TLS (high).** A TLS connection took 128 KiB of the shared buffer budget at accept and held it until its handshake deadline, so enough silent connections stalled every other connection, and the budget did not come back. TLS buffers are now taken when the first bytes arrive, unfinished handshakes hold at most a quarter of the budget, and a worker gives back buffers it no longer needs.
- **Unix sockets (high).** Binding in a directory other users can write to set the mode and owner by path, which a link put in place could point at another file. They are now set relative to the open directory, or inside a private directory; a directory every user can write to without the sticky bit is refused with `ConfigReason::InsecureDirectory`.
- **Windows named pipes (high).** A pipe name with `/` or `..` could open a file or a network path. Names with `\` or `/`, the names `.` and `..`, and names over 247 characters are refused. A name with `/` used to mean a nested pipe name; use another character.

## Added

- `ConfigReason::InsecureDirectory`, `PoolStats::freed`.

## Who should upgrade

Everyone on 0.6: `cargo update -p net-io`. 0.7.2 carries the same fixes for 0.7. Older versions with these defects are yanked once both patches are out.
