# net-io v0.3.0 - Core

**TCP servers and clients with every limit enforced, on Linux, macOS, and Windows.** v0.3.0 is the first release of net-io with working code: TCP listeners and connections, a bounded blocking worker pool, the caps, deadlines, and minimum transfer rate that stop a peer from holding what it should not, the gate seam, sans-IO sessions, kill from any thread, and graceful drain.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies; the few OS calls `std` does not expose go through the crate's own small, tested FFI layer.

## What's in 0.3.0

- **One call to serve.** `net_io::serve(addr, handler)` runs a handler per connection on a pool worker; `net_io::serve_sessions(addr, factory)` drives a sans-IO protocol session per connection. `ServerBuilder` adds listeners with their own limits, a gate, an event sink, and a control line.
- **Limits by default.** Global, per-listener, and per-source caps (sources grouped by network prefix) refuse before any byte is read. Idle, read, write, exchange, and park deadlines, plus a minimum transfer rate in each direction, close slowloris peers and slow readers. A full worker pool refuses with `Busy` instead of queueing without bound.
- **The gate seam.** A `Gate` admits each connection before any byte is read and is asked before every write; a revoked connection cannot send another byte, and the gate learns how every connection ended.
- **Closing well.** Every connection closes once, with one `CloseReason` and one event. Graceful closes protect a reply from being destroyed by a reset; a drain closes idle connections at once and waits for busy ones until its deadline; `kill` works from any thread and never touches a socket that was already closed.
- **Fast where it counts.** A keep-alive round trip costs 2 system calls on Linux (3 on macOS and Windows), no allocation after warm-up, and stays within a fraction of a microsecond of a bare `std` echo. Numbers and method are in `docs/PERFORMANCE.md`.
- **Tested against what goes wrong.** Socket tests for every limit, hook, and close reason; a property test that random interleavings of FIN, RST, kill, timeouts, and drain still give exactly one close; fault injection for OS errors that are hard to produce (out of descriptors, short writes, interrupted calls); loom models of the cross-thread state; Miri; and a descriptor leak test over 100,000 connections.

## Platform notes

Windows waits with `WSAPoll` before every receive, because Microsoft documents a socket whose blocking receive timed out as being in an indeterminate state. On Windows, set `ListenOptions::send_buffer` on internet-facing listeners: send-buffer autotuning otherwise lets a peer that never reads absorb tens of megabytes before the write timeout can fire. Details for every platform are in `docs/PLATFORM-NOTES.md`.
