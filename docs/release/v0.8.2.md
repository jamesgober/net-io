# net-io v0.8.2 - Patch

**UDP sockets on the reactor driver, and `reactor` built on its own.** No API change: every 0.8 program builds unchanged.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies.

## Fixed

- **Windows refused UDP sockets in `Driver::register`.** Before registering a socket the IOCP driver checks that it is not a listener, and it asked whether the socket listens before asking its type. Windows answers the first question with an error for a datagram socket, so every UDP registration failed. The type is checked first now, on every platform: only a stream can listen.
- **A second queued datagram was never delivered on Linux, macOS and FreeBSD.** The readiness driver took a read shorter than its buffer to mean the socket was empty. A UDP socket returns one datagram per read, so a second one already waiting raised no new readiness event and its `Receive` waited forever. On a socket that is not a stream, only `WouldBlock` marks it empty now. A stream keeps the short-read rule, which is exact for it: the queue was empty when the read returned, and the next arrival raises a new event.
  - Cost: one `getsockopt` when `Driver::register` takes a socket; nothing per read, and nothing on TCP. Measured through serve-net 0.8.4's compare harness on loopback (Linux, 32 CPUs, 16 for the server and 16 for the load, under other load), net-io 0.7.3 against 0.7.3 with this change, alternating in one run, median of 5 rounds of 8 s: 64 connections one request at a time, 485,815 against 481,276 requests/s; 256 connections, 1,030,564 against 1,025,162; 64 connections 16 deep, 6,046,428 against 6,017,800. The differences (0.5% to 0.9%) are inside the spread between rounds of one side (4% to 7%), as they should be: serve-net's TCP connections do not take the changed path. serve-net's full test suite passes on the change.
- **`features = ["reactor"]` without `proxy` did not compile.** The PROXY parser's type was named outside its feature. CI now lints every feature on its own on every OS and toolchain.

## Who should upgrade

Anyone who registers UDP sockets with `new_reactor_driver`, and anyone building with a reduced feature set: `cargo update -p net-io`.

## What's next

`0.9.0`: beta and release candidates, with the API frozen once consumers stop asking for changes, a 72-hour soak, and every `unsafe` block checked again against its safety comment.
