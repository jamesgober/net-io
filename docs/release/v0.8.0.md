# net-io v0.8.0 - Alpha

**What the first consumers asked for.** v0.8.0 adds what bouncer-io, serve-net, and tls-net needed to run on net-io: a close that delivers the last bytes before it ends a connection, a drain that tells a session first, workers kept for a listener, and a faster TLS path on the reactor. It also fixes a set of lower-severity defects across the drivers, UDP, and Windows. Every 0.7 program builds unchanged; a UDP server above 100,000 datagrams a second must now raise its global budget (see below).

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies.

## What's in 0.8.0

- **Flush-then-close.** After a gate denial whose bytes went out, the connection stops reading, sends what is queued, sends FIN, and discards input until the peer's EOF or `Limits::denial_linger` (100 ms by default; zero keeps the old immediate reset). It lingers in any phase, so a request already crossing the denial does not turn into a reset that destroys it. On Windows this stops the formatted denial being lost. Cost: a denied connection holds its descriptor up to the linger, and `Limits::denial_linger_max` (a sixteenth of `max_connections` by default) caps how many linger at once; past it a denial resets as before.
- **`ServerHandle::close_after_flush(id, reason, within)`.** A soft kill by connection id: the session's queued output goes out within the bound, then the connection closes the same way. A later `kill` upgrades it to a reset. bouncer-io's ejector uses it.
- **`Session::on_drain`.** A drain tells an idle session once before it closes the connection, so a WebSocket can send its Close frame. The default, `Close`, keeps the old behaviour; any other step keeps the connection until the session closes it or the drain deadline passes.
- **`Limits::first_request_grace`** (1 s by default). A drain does not close a connection that was just accepted and has sent nothing, so a client that connected as the drain began still gets its first request answered.
- **`ListenerSpec::workers(n)`.** On the reactor a listener gets workers of its own, so an admin listener keeps answering while the shared workers are busy.
- **Per-worker accept on the Linux reactor.** A `per_worker` listener accepts in each worker's own event loop, with no accept thread and no wake between threads for each connection.
- **TLS on the reactor.** The records the TLS engine writes as its handshake ends leave with the first reply, and a reply before `Step::Close` carries `close_notify` in the same send: a full exchange with a closing reply goes from 4 sends to 2.
- **Closes after a reply at open.** A connection whose session wrote while idle with no request to answer (a reply in `on_open`, a push between exchanges) lingers on a graceful close, so the client's request crossing it does not cost the client the reply.
- **No gate needed to build.** A server builds without `.gate(..)`; `NoGate` admits every connection, as `AllowAll` does. A server facing the internet should still set one.
- **UDP budgets per prefix.** A UDP source is now a prefix (IPv4 /32 and IPv6 /64 by default, `UdpOptions::source_prefix`), so one IPv6 host no longer gets a budget per address. A new source starts with a burst of 16 (`new_source_burst`). Every socket now has a global budget by default, `UdpBudget::GLOBAL_DEFAULT`: 100,000 datagrams a second and 150 MB a second. A server that expects more raises it with `UdpOptions::global_budget`. The source table costs about 200 bytes per source.

## Fixed

- A reactor worker that stopped on a panic kept receiving connections that nobody served, and drain and shutdown waited for it. It now takes no more connections, and `Stats::workers_lost` counts it.
- A drain, a shutdown, and `remove_listener` return at most about 2 s after their deadline even when a blocking handler ignores its kill. That thread is left running on its own and counted in `Stats::workers_detached`.
- A connection dropped by a panic could leave its kill handle able to close a later socket. The handle now ends with the connection.
- Linux: a file send to a peer that had reset could raise SIGPIPE. It no longer can; the mask costs about 2 to 4% of a 64 KiB send.
- `SendFile` with length 0 now sends nothing on every platform, and `recv_file` reports a file write failure instead of losing bytes.
- Unix: a signal no longer fails a blocking connect.
- UDP: a non-blocking receive returns under a flood of dropped datagrams, and more ICMP-driven errors are skipped instead of ending a receive loop.
- A PROXY v2 `LOCAL` header is accepted whatever its address family.
- Windows: `reuse_address(true)` is ignored, so no other socket can bind over a listener; a hand-off can reuse a freed handle value; named-pipe closes to a client that never reads wait a bounded time in total.
- On the blocking driver, a drain that ended a graceful close's linger reported it as a kill; it keeps the close's own reason now.
- A refusal shows in `Stats` by the time the client sees it.

## Tested

- The full suite on Linux, macOS, and Windows, on stable and 1.85, on every feature set, plus the fault-injection tests and the model-checked concurrency tests.
- A 24-hour soak with normal and hostile peers on each driver on Linux and on Windows (one driver at a time), and 5.5 hours on each driver on macOS, the most GitHub's hosted runners allow. All of them finished clean.

## Known gaps

The register in `dev/ROADMAP.md` lists what is accepted for now, each with its reason and the version that closes it. The executor adapter waits for a published `task-io` with a driver seam. On macOS a client whose receive buffer is full can miss the reset of a connection the server killed, and waits for its own read timeout. A gate's `admit` must return promptly: a stop still waits for it.

## Who should upgrade

Everyone on 0.7 who wants the new close and drain behaviour, or the fixes above. Programs that stay on 0.6 or 0.7 already have the security fixes through 0.6.3 and 0.7.2.
