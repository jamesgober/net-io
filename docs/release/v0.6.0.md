# net-io v0.6.0 - Optimisation

**Measured against the other Rust stacks, files without copies, and UDP in batches.** v0.6.0 adds a harness that runs one load generator against `std`, `mio`, `tokio`, `monoio`, and net-io, the benchmarks B-1 to B-14 with their numbers, zero-copy file sends, UDP batches and UDP sessions on a server, and the remaining P2 options.

## What is net-io?

The network IO substrate for the `-io` and `-net` crates: listeners and sockets, the life of each connection, the limits and timeouts around it, graceful drain and restarts, and the seams a connection gate and a TLS engine plug into. It is protocol-free and has no runtime dependencies; the few OS calls `std` does not expose go through the crate's own small, tested FFI layer.

## What's in 0.6.0

- **Files without copies.** `TcpConnection::send_file` and `Output::push_file` send a file by `sendfile` on Unix and `TransmitFile` on the Windows reactor, and by reading in pieces where those do not apply. The gate checks every MiB, and a file that ends before its promised length fails the connection with the count sent.
- **UDP in batches.** `recv_batch` and `send_batch` move up to 64 datagrams per system call on Linux (`recvmmsg`, `sendmmsg`), with the per-peer budget still applied to each datagram. Packet info on Unix, multicast joins, and `UdpSession` listeners on a server, with the door, stop, and drain of a TCP listener.
- **Load-aware limits.** `Pressure` shrinks handshake and idle deadlines as the server fills, and `Limits::lane_reserve` keeps slots for the lanes that matter most.
- **Options.** `defer_accept`, `fast_open` (off by default: its first data can be replayed), `incoming_cpu`, `user_timeout`, per-worker `SO_REUSEPORT` listeners on Linux, `Placement` for pinning workers, `lockdown_allowed`, and the PROXY encoders `encode_v1` and `encode_v2`.
- **The competitor harness.** `compare/` runs the same echo on every stack, each in its own process, and reports throughput, latency to p99.9, and server CPU per round trip. CI runs it on every change.

## Security

**Upgrade from 0.5.0 if you run sessions on the reactor.** In 0.5.0 the reactor did not apply the minimum transfer rate to a peer that sent more often than the check interval (1 s by default): each arrival moved the check later, so a client sending one byte every 40 ms after an opening burst held its connection for as long as it kept sending, which is the slowloris attack the rate exists to stop. 0.6.0 checks the rate on every arrival and every send completion, at an estimated 10 to 20 ns each. The blocking pool and `BlockingHandler` servers were not affected. 0.5.0 is yanked from crates.io for this reason; lockfiles that already name it still build.

## Fixed

A buffer moved into an output with `push_buffer` was never handed back, so an echo that swapped its input took a fresh 16 KiB buffer, and its page faults, on every round trip: about a fiftieth of the copying echo's rate. An output now keeps one spare and returns the rest to the worker's pool as each send completes. The allocation test now covers every driver and that path.

## Performance

`docs/PERFORMANCE.md` has every number. On GitHub's 4-vCPU runner, where the load generator shares the CPU, net-io's reactor runs at 0.88x to 1.07x tokio across the shapes, with its limits, deadlines, gate, and buffer wiping on. On the 32-thread build host it is about 2x tokio on 16 KiB messages. Raw `mio`, with none of those protections, is ahead of net-io on most shapes; the plan's goal of 1.2x the best competitor is not met. The miss is accepted for 0.6.0 only: the gate runs again on a dedicated, quiet load machine in the pre-1.0 polish milestone, and before 1.0 it is met or the target is derived again with the reason written down. The register in `dev/ROADMAP.md` records the gap. An idle connection costs 1,239 bytes of process memory at 10,000 connections and 511 at 100,000, against 8,993 for tokio. macOS now makes 3 system calls per round trip, down from 3.05 to 3.13.

Wiping released buffers, which keeps one peer's bytes from reaching another, costs about 4% at 16 KiB and stays on by default.

## Platform notes

Packet info is Unix only. Per-worker listeners are Linux only and cannot be handed off. The std-only fallback for other targets moved after 1.0: without `poll`, `std` cannot wait on a socket and a wake together. Details are in `docs/PLATFORM-NOTES.md`.
